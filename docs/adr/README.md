# ADR — Registro de decisiones de arquitectura (quini-api)

Formalización, una decisión por fichero, de la tabla "ADR-lite" (D1-D26) definida en `docs/00-Plan-inicial.md` §3. Cada ADR documenta contexto, decisión, alternativas descartadas y consecuencias reales verificadas en el código y el despliegue.

| #   | Decisión                                                                          | Elegido                                                                                                                                       |
| --- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | [Framework HTTP](./0001-framework-http.md)                                        | Express 5                                                                                                                                     |
| D2  | [Lenguaje y sistema de módulos](./0002-lenguaje-modulos-esm.md)                   | TypeScript + ESM (`"type": "module"`)                                                                                                         |
| D3  | [Validación de entrada](./0003-validacion-de-entrada.md)                          | Zod                                                                                                                                           |
| D4  | [OpenAPI](./0004-openapi-code-first.md)                                           | Generado desde Zod (code-first)                                                                                                               |
| D5  | [Acceso a datos](./0005-acceso-a-datos-drizzle.md)                                | Drizzle ORM + migraciones SQL                                                                                                                 |
| D6  | [Motor de base de datos](./0006-motor-de-base-de-datos.md)                        | PostgreSQL 18 en los tres entornos                                                                                                            |
| D7  | [Base de datos en desarrollo local](./0007-base-de-datos-local.md)                | Docker Compose (por defecto) + embedded-postgres (opcional)                                                                                   |
| D8  | [Formato de los tokens de sesión](./0008-formato-de-token.md)                     | JWT propio (access) + token opaco (refresh)                                                                                                   |
| D9  | [Algoritmo de firma JWT](./0009-firma-jwt.md)                                     | HS256 en desarrollo → RS256 en producción                                                                                                     |
| D10 | [Librería JWT](./0010-libreria-jwt.md)                                            | jose                                                                                                                                          |
| D11 | [Hash de contraseñas](./0011-hash-de-contrasenas.md)                              | Argon2id (`@node-rs/argon2`)                                                                                                                  |
| D12 | [Framework de testing](./0012-testing.md)                                         | Vitest + Supertest                                                                                                                            |
| D13 | [Estructura de código](./0013-estructura-de-codigo.md)                            | Modular por feature, en capas                                                                                                                 |
| D14 | [Logging](./0014-logging.md)                                                      | pino + pino-http + requestId                                                                                                                  |
| D15 | [Versionado de la API](./0015-versionado-de-api.md)                               | Prefijo `/api/v1`                                                                                                                             |
| D16 | [Cliente de pruebas manuales](./0016-cliente-de-pruebas.md)                       | Insomnia + colección versionada + `inso` CLI                                                                                                  |
| D17 | [Forma de las rutas con temporada](./0017-rutas-con-temporada.md)                 | Rutas planas `/api/v1/jornadas/{n}` resueltas contra la temporada activa, con `?temporada=<codigo>` para apuntar a otra                       |
| D18 | [Acceso cerrado por invitación](./0018-acceso-cerrado-por-invitacion.md)          | Invitación de un solo uso, emitida por un admin, con TTL de 7 días; también obligatoria para el login con Google                              |
| D19 | [Autorización](./0019-autorizacion-por-rol.md)                                    | Por rol (`user`/`admin`) en el claim del JWT, con middleware `requireRole`                                                                    |
| D20 | [Envío de invitaciones](./0020-envio-de-invitaciones.md)                          | Sin email por ahora: el endpoint devuelve la URL y el admin la reparte a mano                                                                 |
| D21 | [Estrategia de despliegue](./0021-despliegue.md)                                  | VPS con Docker Compose + Caddy (HTTPS automático), imagen publicada en GHCR                                                                   |
| D22 | [Migraciones en producción](./0022-migraciones-en-produccion.md)                  | Paso explícito antes de arrancar la nueva versión, en un contenedor de un solo uso                                                            |
| D23 | [Observabilidad: métricas y alertas](./0023-observabilidad-metricas-y-alertas.md) | `prom-client` en la API + Prometheus + Grafana OSS autoalojados, más Uptime Kuma fuera del VPS                                                |
| D24 | [Observabilidad: trazas](./0024-observabilidad-trazas.md)                         | OpenTelemetry preparado pero desactivado (`OTEL_ENABLED=false`); se activará cuando haya un problema de rendimiento que los logs no expliquen |
| D25 | [Seguimiento de errores (tipo Sentry)](./0025-seguimiento-de-errores.md)          | Aplazado; si hace falta, GlitchTip (compatible con el SDK de Sentry)                                                                          |
| D26 | [Automatización de módulos con skills](./0026-automatizacion-con-skills.md)       | Una sola skill, `/quini-api-new`, prevista para escribirse después de tener un módulo terminado a mano                                        |
